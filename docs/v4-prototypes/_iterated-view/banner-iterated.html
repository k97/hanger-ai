The category track and the summary strip

One control, and the surface whose figures it changes. The track is a specification, not a comparison: Karthik ruled on 2026-08-22 in favour of the raised capsule, and the three alternatives it was drawn against — tonal, filled, and counts on the selected segment only — are gone. The loose chips become one continuous track and the selected category is a capsule that slides inside it: position in the track says “selected”, so the check mark goes. The labels and the backend counts stay, and so does hide-at-zero with All, the selected category and MCP servers exempt (CategoryFilterCards.tsx). The slide is the app’s one spring over --dur-nav. visionOS’s glass is out — no blur. The capsule carries a tight contact shadow and no border, which is the substance of the ruling: a second, smaller elevation beside the map’s, proposed as --capsule-shadow. Two further rulings placed it. Karthik, 2026-08-22: the track moves above the strip, because once the strip’s figures follow the selected category the track is the control for those figures and belongs above what it changes — the same reasoning that put Rescan inside the strip. Karthik, 2026-08-23: the strip’s row is that track and not a second control that merely resembles it, so both draw from the same .track in _proto.css. The shell below is one window at true size, 1024×700 cropped to 440px, with MCP servers selected, and the meter, the legend and the facts line are all its figures. Every number is from this machine’s store; the annotations beside the shell say which are backend fields already and which still need a ruling. Click a segment, or focus one and use the arrow keys then Enter.

The same ruling settled dark. A shadow is invisible on black, and --page on --plane is one value step — so in dark the capsule lightens instead of casting a shadow nobody can see, the way iOS’s does. Its surface is a proposed token, --capsule: --page in light, --tint in dark. Flip Dark to judge.

Open · semantics

CategoryFilterCards renders buttons with aria-pressed (filters). Drawn as a tab view, role="tablist" / role="tab" + aria-selected fits: the list below changes with the category. Arrow keys move between tabs; the indicator follows focus only on selection. Which of the two the shipped control carries is still a ruling to make.
