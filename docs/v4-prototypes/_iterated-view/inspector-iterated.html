Browser Automation with agent-browser

Quick start

agent-browser open <url>        # Navigate to page
agent-browser snapshot -i       # Get interactive elements with refs
agent-browser click @e1         # Click element by ref
agent-browser fill @e2 "text"   # Fill input by ref
agent-browser close             # Close browser

Core workflow

  1. Navigate: agent-browser open <url>
  2. Snapshot: agent-browser snapshot -i (returns elements with refs like @e1, @e2)
  3. Interact using refs from the snapshot
  4. Re-snapshot after navigation or significant DOM changes

Commands

Navigation: open, back, forward, reload, close. Snapshot: snapshot -i for interactive elements, snapshot -a for the full tree.

Section format (Karthik, 2026-08-22): an eyebrow, then one bordered card of icon · label · value rows, dividers only between rows — the “In this skill” card applied everywhere.
Actions are a mini set (Karthik’s reference, 2026-08-22): equal outlined pills, icon + label, 26px. Link to… loses its fill here to match the set; if it is to stay the one strong action (--fill), it is this size with the fill — a ruling.
Tabs, content first. Karthik’s ruling, 2026-08-22: the breakdown leads — Content for a skill, Tools for an MCP server — and Details comes second. Click a tab to flip. The header, state line, path chip, actions and the routed issue line stay above the tabs: they belong to the asset, not to a tab.
Underline tabs (Karthik’s reference, 2026-08-22): labels on a --line baseline, the active one in --ink-1 medium with a 2px --ink-1 rule beneath; the label’s weight and the rule are the only things that change. The pane’s category selector is a segmented track, the inspector’s tabs are underline tabs — two idioms for two jobs: one filters a list, the other switches views within a surface.
Described in. The prototype’s “token tax”: probe.rs drops the schema today; keeping its byte size is a small backend change. Tokens are not measurable, bytes are — the dash holds the column until they arrive.
MCP header. No path chip and no actions: an MCP server has one config path per registration, and those live under Details › Registered in. The state line is the list row’s subline, coloured as the verdict’s dot. Tool rows carry the server’s own descriptions, as probed on this machine.
Said once (Karthik, 2026-08-22). Transport and the launch were repeating four times — a header pill, a section head, a row, and three identical registration lines — so they fold into Identity & capabilities, and Links with them (“Runs from” IS the launch read another way). The launch returns to the registration rows only when the launches DISAGREE: that is when it is the finding, and the verdict card above says which. Divergence is what distinct_spec_count and agreement already report per row.
Identity & capabilities. The handshake lists the capability keys a server advertises (probe.rs:602-606); absence reads “not offered”, never “unsupported”. One row per key, so the pills that restated server and protocol are gone.
Transport. The prototype’s one Command/Arguments block would have to pick a registration or hide divergence. One row states the kind; the launch itself is redacted, and raw args never cross IPC (no-launch-args-in-ipc.test.ts). Per-registration launches return when they disagree.
Runs from is derived from the launch, no network: an npx/bunx runner names an npm package → its npm page; uvx → PyPI; a remote transport → its endpoint host; an app bundle → Reveal in Finder. A repository or docs URL is not known — Hanger reads no registry — so no such row is drawn.
Context. The prototype’s “Context bloat”: bytes are measurable once probe.rs keeps the schema size (medium backend); tokens are not — a tokenizer estimate can follow, labelled by its BPE. A collision is a Needs-review finding, stated once and routed, not a red box. The 10.8 kB is illustrative — nothing measures it yet, hence “pending backend”.
Identity · Modified. Modified is the file’s mtime, read at request time like link state — a small backend addition (read_asset_body or the annotation can carry it). “Primary owner” and “Last reviewed” have no source: the frontmatter the scanner keeps is name, description, version, source-origin (scanner.rs:433-440), and Hanger reads no git. “~100 tokens” stays as kB · lines; “Structural pattern” has no taxonomy behind it.
Capabilities. A restatement of the declared field, not a rating: the allowed-tools row names the tool and what it does — “runs commands”. The exploration’s “Tool exposure: Optimized” and “Privilege boundaries · Risk: Med” have no data behind them — the harness has no tool groups, and a risk level is a judgment; if the app is ever to rate shell access it is a Needs-review issue kind and a ruling, not a panel box.
Open question: is the active tab remembered per kind (a preference, like inspector_width) or does every open start on the breakdown?
