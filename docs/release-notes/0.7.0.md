Hanger can now switch MCP servers and skills off and on, and shows what each
engine spends on its servers every session.

## Switch an MCP server off for one engine

A server's row carries a mark for each engine that loads it, and each mark is a
switch. One switch in the server panel's header covers every engine at once, and
⌘K switches a server when you type its exact name.

Hanger makes the change the way each engine expects. For Codex it sets the
server's `enabled` key. For Gemini CLI it writes Gemini's own enablement file.
For Claude Code it goes through Claude Code's own `claude mcp` command, and keeps
a copy of the entry so it can put it back exactly. Claude Code servers can be
switched from its user config. Other engines are shown but not switched yet.

Before every write Hanger saves a copy of the file. It then replaces the file in
one step, reads it back to check the change, and offers Undo. A switch changes
what the engine's next session loads. A session that is already running keeps
the servers it started with.

A server you switch off stays in the list, in a group of its own. Its panel says
when you switched it off and whether a file still declares it.

## See what each engine costs

The overview card ranks your engines by how many tokens their MCP servers' tool
descriptions add to every session. Pick an engine to see its figure by kind.
Only MCP servers are measured so far. Skills, rules and subagents say "Not
measured" rather than guess. A server Hanger has never asked for its tools isn't
in the figure, and the card says how many servers it covers. Measure all asks
the rest, but only when you click it.

The card sits at the top right of Global when there's room. When there isn't, it
opens from the window bar or with ⌘E.

## Switch a skill off

A skill in your global store has an On/Off switch in its panel header. Off moves
the skill's folder into Hanger's own keep and removes the links that pointed to
it. On puts the folder and every link back where they were. Switched-off skills
collect in a group of their own, and Undo works the same way it does for servers.

## Global, rearranged

Global and each repository now show their assets as two-line rows in a centred
column. Tick marks beside the list jump between groups, and hovering one shows
the group's name and how many it holds.

## Faster scans

A scan now reads the global store once, not once per linked folder, and writes
everything through a single database connection. Opening a server's panel no
longer starts a rescan.

## Fixes

- VS Code's MCP servers are read from where VS Code now keeps them.
- An editor opens at the path Hanger found it at. One installed outside
  /Applications, or under another file name, now opens too.
- Opening a server's panel no longer starts a server that every engine has
  switched off.
- An engine with nothing measured says so, instead of showing ≈ 0.
