Hanger now answers questions from your coding agents, treats Antigravity CLI as an engine of its own, and gives a repository the same overview Global has.

## Ask Hanger from inside an engine

Hanger has its own MCP server. Add it to Claude Code, Codex or any engine that
takes MCP servers, and the engine can ask Hanger:

- which engines are on this Mac;
- what each engine's MCP servers cost in tokens;
- where a skill, rule, subagent or server lives;
- which engines read it;
- what's broken or failed to parse.

The server only reads. It changes no file, leaves out launch commands and
environment values, and doesn't start Hanger's window.

To add it to Claude Code:

```
claude mcp add --scope user --transport stdio hanger -- "/Applications/Hanger AI.app/Contents/MacOS/Hanger AI" mcp
```

The lines for the other engines are in `docs/mcp-server.md` in Hanger's
repository. Open Hanger once after updating and let it finish a scan. Until
then the server says it has nothing to answer from yet.

## Antigravity CLI is its own engine

Hanger reads Antigravity CLI from `~/.gemini/config`, apart from Gemini CLI,
so each shows its own skills and MCP servers. You can switch Antigravity CLI's
servers off and on like any other engine's. Hanger marks a server off with a
`disabled` key in `mcp_config.json`, and `agy mcp list` then shows it as
disabled.

Antigravity CLI keeps no skills folder inside a project. So deploying one of
its skills to a repository now stops and tells you why.

## Repositories look like Global

A repository opens with the overview card, docked beside the list or behind
⌘E when the inspector is open. The card shows the repository's engines, its
assets and the nested repositories inside it. The kind tabs sit above the
list, and Esc clears the inspector, as it does on Global.
