Hanger now tells you where an asset came from, and the window sits on macOS's
own material.

## Every asset says where it came from

The inspector's Details tab used to answer this by reading a `source-origin`
key out of frontmatter. Nothing in the wild writes that key, so every asset on
every machine read "Local · not from a registry" — a confident answer that was
the same answer for everything.

Hanger now resolves origin during the scan. Details shows the repository or
package an asset came from as a link you can open, a tooltip saying how Hanger
knows, and a disclosure with the pinned commit, the plugin that delivered it
and when it was installed. Skills, rules, subagents and MCP servers all carry
it, and an MCP registration shows its origin where the panel lists it.

When there is no origin to show, the row is gone rather than saying so. The
Path row two lines below already tells you where the asset lives.

The detectors read formats, not this machine: a plugin store's layout, a
package manifest, a checkout's remote, a marketplace's flags. An asset that
came from somewhere Hanger has never seen reports nothing rather than
guessing.

## The window sits on the system's material

The sidebar is translucent and picks up what is behind the window, the way
native macOS apps do. Before React mounts, the window shows the material with
the Hanger mark at its centre instead of a white flash. The 1px window edge
macOS stops drawing for translucent windows is painted back at the window's
own corner radius, and the sidebar's colours are re-based on the new surface
so nothing drifts between the rail, the source list and the panes.

## The inspector holds its place

Four changes, all from using it:

- The tab you opened stays open as you move between assets. Reading Details
  down a table no longer snaps back to the document on every row.
- Filtering the table by category no longer empties the panel. The inspector
  holds what it has until you pick another row.
- The resize handle has no ceiling. Drag it as wide as you like; it resists
  where the content column reaches its minimum, and past that snaps to the
  full window and drags back out again. Below that minimum the content column
  scrolls sideways instead of clipping.
- Expanded with the source list collapsed, the panel's own header now clears
  the traffic lights, and the resize cursor holds for the length of a drag.

## Hanger looks in more places for MCP servers

VS Code's per-profile `mcp.json` files, `~/.mcp.json` as a home-level Claude
Code source, system-wide `managed-mcp.json`, and Gemini's system settings.

One caveat if your machine is managed: when `managed-mcp.json` is present it
takes exclusive control of Claude Code's MCP configuration and suppresses the
other sources. Hanger reads it, but still shows those suppressed sources as
reaching your assets. If you are on a managed fleet, treat Claude Code's Reach
for MCP servers as unreliable this release.

## Fixed

- Diagnostics: repeated log lines collapse, so the tail carries history
  instead of eighty copies of one line.
- The rail's count badge no longer draws a ring in a colour the surface
  underneath it no longer uses.
- A dev build now names its own window, so a screenshot cannot silently be of
  an installed copy running beside it.
