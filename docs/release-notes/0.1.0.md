The first release since Hanger's interface was rebuilt. 284 user-visible changes
since 0.0.3. The full list is in
[CHANGELOG.md](https://github.com/k97/hanger-ai/blob/v0.1.0/CHANGELOG.md).

## Eleven engines

Version 0.0.3 recognised four. This release tracks eleven engines that own
directories: Claude Code, Codex, Gemini / Antigravity, Kiro, Trae, OpenCode,
Amp, Zed, Roo Code, Kilo Code and Cline. Each one carries its own brand mark in
the table, the sidebar and the inspector instead of a monogram.

Ownership and reach are kept separate. An engine that reads the shared
`.agents` convention now says so without claiming to own what it finds there.
Zed owns no directory at all and is detected by its config file, so it appears
as a reach tile rather than a root.

## MCP servers

Hanger could not see MCP servers before this release. It now reads
registrations from sixteen hosts, including Cursor, VS Code, Claude Desktop,
Devin Desktop and Claude.ai connectors, across eight config dialects with a
JSONC pre-pass. A format Hanger cannot read says so rather than showing up as
an empty result.

Servers group by what they actually launch, not by the file that declares them,
so the same server registered in four places is one row with four
registrations. Hanger flags the case where those registrations disagree about
the launch. It can verify a server by handshake to list the tools it exposes,
and it reads the process table to report which servers are running and which
are unaccounted for.

Secrets are redacted before anything reaches the screen. Launch arguments no
longer cross the IPC boundary at all.

## The link map

A map of which engines reach which assets and by what mechanism. Nodes carry
per-kind counts and the rules that live there. Hovering a node dims everything
it does not reach. Layer switches isolate unlinked roots, or only drift and
dangling. When an edge is faulty, a state dot appears on the node it arrives
at.

Link state is computed from the filesystem on every read rather than cached, so
a link that broke outside Hanger shows as broken the next time you look.

## Interface

Four full-height columns on a mono palette, each with its own cap. The
inspector opens on row selection with Content and Details tabs, a preview that
suits the file type, and folder listings for skill directories. Needs review
became a section that carries cross-repo issues rather than a badge.

The theme follows the system appearance unless you pick one explicitly.
Tooltips reach icon-only controls. Scanning, loading and empty states now have
animated marks, and every one of them holds still under Reduce Motion.

## Upgrading

The store migrates from schema 2 to schema 7 on first launch. Migrations run
forward only: an older Hanger will open a migrated store without putting it
back, so downgrading to 0.0.x is not supported. The store lives at
`~/Library/Application Support/com.rkarthik.hanger/hanger.db` if you want a
copy first.

Asset reaping stays off unless `HANGER_ENABLE_REAP` is set, unchanged from
0.0.x.

If you are on 0.0.1 (published at the time as 1.0.0), in-app updating will not
work. That build shipped a different updater key and cannot verify anything
signed since, which is what 0.0.2 fixed. Download the DMG below instead.

## Install

macOS universal build, signed and notarised. Download the DMG below.

Every build published before this one carried a 1.x version number, so none
of them will update themselves to 0.1.0. This install is a one-time manual
step. From 0.1.0 onward, Check for Updates works as normal.
