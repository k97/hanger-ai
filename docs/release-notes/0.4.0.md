When macOS blocks a folder, Hanger now says so instead of showing you less.

## Blocked folders are a finding, not an empty pane

macOS guards Desktop, Documents, Downloads, iCloud Drive and external drives.
When it refused Hanger a folder, the scan quietly returned fewer assets — or an
empty pane, which read as "there is nothing here" rather than "macOS said no".
Hanger was testing for the wrong error: macOS denies with "Operation not
permitted", not "Permission denied".

A blocked folder now reports itself. If the folder is a project you linked, the
pane says macOS is blocking it and offers **Choose Folder Again** — picking a
folder is how macOS grants access, so re-choosing it restores the scan. If it is
an engine's own folder, the warning names the engine, so you know an engine may
be installed that Hanger cannot see.

The panel used to send you to System Settings. That never worked: apps only
appear in Files & Folders after macOS has prompted for them, and there is no way
to add one by hand.

## macOS prompts now say why

Hanger ships the five permission descriptions macOS shows in its own consent
dialog, so a prompt explains what Hanger wants the folder for instead of using
Apple's generic wording.

## Fixed

The inspector's derivation notes moved behind an info popover, and each trigger
is now named for the section it belongs to.

Fifteen elements across six files named animation classes that were never
installed, so they rendered with no motion at all. Every one now uses a real
utility. Dragging the sidebar no longer trails the cursor.

A failed MCP probe no longer reports a zero-cost ledger; an unmeasured server
says it is unmeasured.
