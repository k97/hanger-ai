Hanger now also sends its usage events and crash reports to PostHog, but only
the ones you've already allowed.

## What is sent, and when

The two choices in Settings stay the only switches. With usage analytics on,
Hanger sends a short event when you switch an MCP server or a skill, link an
asset, link repositories or open a Discovery directory. With crash reporting
on, it sends errors the app didn't handle. Turn either off and that kind stops
at once. Usage analytics are still on by default and crash reporting is still
off, as before.

None of these events carries a file path, an asset name, a server name or a URL.
Hanger doesn't record what you click, doesn't record your session, and doesn't
load any script from PostHog. The telemetry page in Hanger's repository,
`docs/telemetry.md`, lists every event and field.

Google Analytics and Sentry are unchanged.
