Assets open in your editor, anything is a keystroke away, and Hanger now sees
the MCP servers a parent directory hands your project.

## Open an asset in your editor

Every asset now opens where you actually work. Hanger detects the editors
installed on your machine — thirty-six of them, not the five it started with —
and the first time you open something it asks which one you want, then
remembers. Settings has a pane to change that later, and holding Option opens a
single asset somewhere else without disturbing the default.

This shipped alongside the reason it had never worked: the permission scope
Hanger asked for could not reach a single asset it owns. Every path Hanger
tracks has a dot in it — `~/.claude`, `~/.codex`, a project's own `.claude/` —
and the scope refused every one of them, silently. An editor that is named but
not installed now reports the failure instead of appearing to succeed.

## Find anything without hunting for it

Cmd+K opens a palette over whatever you are looking at. Type a name, press
Enter, and the inspector opens on that asset with its own primary tab already
selected and its row scrolled into view. Results are grouped by kind under
headings.

The palette replaces the search field that used to sit in the inspector cap and
the separate text filters each pane carried. One way in, from anywhere, instead
of four that each worked slightly differently.

## MCP servers a parent directory declares

A project sitting under a directory with its own `.mcp.json` can use the servers
declared there. Hanger previously showed nothing of this, so a project with
working servers looked bare. It now derives that reach when you read the row and
says so on the server card's second line, with the count of ancestors reached
and how many the project is actually using.

The Tools column is filled from the probe cache rather than left blank, and an
engine's summary carries how many hosts it spans and how many tools that comes
to in total.

## A skill reads like a document

The inspector's Content tab renders the markdown a `SKILL.md` actually uses —
headings, lists, tables, fences and inline code, each on its own leading — where
it used to show a wall of undifferentiated text. A tool's description is set as
prose beneath its name rather than crammed into a row.

## Relocated config directories

If you have moved Claude Code's or Codex's configuration with
`CLAUDE_CONFIG_DIR` or `CODEX_HOME`, Hanger now looks there. Engine roots and
MCP sources both resolve through the relocated path, so a machine that moved its
config no longer reports an engine with servers and no skills — an absence that
was Hanger looking in the wrong place rather than a fact about your setup.

## The window, throughout

The sheet carries both of its top corners on every screen, the inspector's
breadcrumb sits in the cap band, and the sidebar toggle is instant — its width
animation had been re-laying out the content every frame. Icons follow one
stroke rule and one box per surface. Text roles are defined once and imported,
so headings, captions and code share a leading rather than each pane inventing
its own.

Dark mode sits the sheet off the floor, and the focus ring takes each element's
own corners.
