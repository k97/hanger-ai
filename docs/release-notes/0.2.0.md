A telemetry release. Nothing changes in what Hanger shows you or how it scans;
everything here is about what the app reports and what it admits when reporting
fails.

## Usage analytics are on by default

The onboarding consent step now arrives with **Enable usage analytics** already
switched on. It is still shown, and still refusable before anything is sent —
turning it off there, or later in Settings, is remembered and survives
restarts. If you have declined before, you stay declined; the new default only
applies where no choice was ever recorded.

Crash reporting is unchanged: opt-in, and off until you turn it on.

Events carry event names and generic category badges. Paths, file contents and
credentials are rejected before dispatch, as before.

## Analytics failures are no longer silent

Hanger reports usage over the GA4 Measurement Protocol. A rejected event used
to be indistinguishable from a delivered one: the code checked whether the
request completed, never what the answer was, so a 401 from a bad credential
looked exactly like success. It now logs any response that was delivered but
not accepted, with its status.

The request URL carries the API secret in its query string, and a failed
dispatch used to write that URL into the application log. It no longer does.

## Upgrading

No store migration in this release; the schema stays at version 7.

If you are on 0.0.1, in-app updating will not work — that build shipped a
different updater key and cannot verify anything signed since, which 0.0.2
fixed. Download the DMG below instead.

If you are running a build numbered 1.x, it will not update itself either. The
release line was renumbered to 0.x, and version comparison reads 0.2.0 as older
than 1.x, so the updater stays silent. Install the DMG once and updating
resumes normally.

## Install

macOS universal build, signed and notarised. Existing 0.1.0 installs can update
in place from Check for Updates.
