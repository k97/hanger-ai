## Findings

**F1 (blocking). The ambiguity fixture can't collide.** `two_names_sharing_127_characters_are_ambiguous` uses `"a".repeat(127) + "x"` and `+ "y"`, which are 128 characters each. `public_name` cuts only names longer than `NAME_CAP = 128`. `mcp_server_tests.rs` pins this: "exactly 128 is not cut". So the two public ids differ, no shared id exists, and the test can never get `Ambiguous`. An implementer will either fail to go green or reshape the test unreported. Fix: use names of 129 or more characters that share their first 127 (e.g. `"a".repeat(127) + "xy"` / `+ "yz"`), and assert both `public_name`s are equal before asking.

**F2 (blocking). The withheld rule passes secret-bearing text that has no ASCII letters.** The rule deletes the name and then checks only "runs of ASCII letters and underscores". These still pass:

- a line whose remaining text is digits or punctuation (a value alone on a changed line, such as `"0123-4567"`);
- non-ASCII keys and values (`"ключ": "12345"`).

Review Focus 1 and the anti-goal ("never … shows one to a model", "Secrets never cross IPC") make this the security-critical algorithm. Simpler and tighter: after deleting the name and the six allowed words, the rest must be only whitespace and the punctuation `{}[]":,=.`. Anything else withholds. Add a test for a digits-only line and a non-ASCII line.

**F3. `scanned` and `measure` are private.** Today `tools::scanned` and `tools::measure` are private `fn`s. T2 calls both from `proposals.rs`, but its Interfaces only list `public_key` becoming `pub(crate)`. Say so, or say the propose functions live in `tools.rs`.

**F4. The skill "on" verb is narrower than Q10.** Q10 allows "on and off". The plan makes skill-on reachable only by `propose_undo`, because no read tool exposes `kept-skill:` keys. It states this under Known limits, which is the right place. It is an interpretation of a permissive answer, so it should be confirmed with Karthik at Gate N rather than inherited. Not blocking: `Ask` can gain a variant later.

**F5. T3 Step 2's expected output can't be observed.** `cargo test --test mcp_server_protocol_tests --test mcp_proposal_tests` aborts on `mcp_proposal_tests`' compile error (`engine_of_client` not found) before any protocol test runs. So "the tool list has 5 entries where 9 are expected" is never printed. Run the two separately, or expect only the compile error.

**F6. The modern-client `asked_by` path has no test.** T3 reads `asked_by` from `peer_info()`, and otherwise from `_meta["io.modelcontextprotocol/clientInfo"]`. Both protocol tests initialize, so only the first path is tested. Add `server/discover` plus `_meta` clientInfo → `asked_by == "claude-code"`. Without it, the second branch is untested code.

**F7. T6 changes the README tests figure but doesn't regenerate it.** T6 adds frontend test files, so `hanger:tests` moves, and Step 4's `readme-sync.test.ts` goes red. T6 neither runs `readmeCounts.ts` nor commits `README.md`.

**F8. `useMcpSwitch.ts` has no owner.** P1, P2 (a `project` argument) and P4 (`loadProfile`, Undo of a load) all modify it in different waves. §5 has no row for it. Name its merge order, or ask the design owner for a row. Otherwise three tracks hand-merge one hook.

**F9. The in-app Undo leaves the proposal reading `undoable`.** After an approval, the notice's Undo goes through `undo_mcp_switch`/`undo_skill_switch`, and the proposal file is never updated. So it still reads `Applied { Some }` and `undoable: true`. The model can then file a `propose_undo` whose preview diffs against a state that no longer exists, and approval fails `not_undoable` or `changed_since_read`. Fail-safe, but the preview is misleading. State it under Known limits, or have the preview return `Unavailable` when the receipt no longer applies.

**F10. `list_mcp_proposals` deletes files.** It runs `sweep` on every 3 s poll, so a command described as a read deletes files. Fine, but its doc comment and the `docs/ipc.md` section should say so.

Checks passed:

- **Assumptions surfaced.** P2's project items preview as `Unavailable`. The folder is not a trust boundary. rmcp `peer_info` was checked in source. Gemini's state-file path is duplicated, under a `shortcut:` comment pinned by a test.
- **Simpler path.** Polling rather than a watcher, with the reason given. Previews duplicate `ops`' lookup rather than change a P2-owned module, and the duplicate is pinned by `approving_previews_match_the_write`.
- **Scope.** Every task traces to §4.1, the §5 owner row or Q10. No speculative scope.

## Verdict

**Needs answers.** Blocking, in order:

1. F1: re-spec `two_names_sharing_127_characters_are_ambiguous` with names over 128 characters, so a shared public id exists.
2. F2: tighten the withheld rule to a character allowlist that fails on digits and non-ASCII, and add tests for both.
