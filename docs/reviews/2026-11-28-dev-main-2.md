**AppKit and unsafe code: no defect found.**
- **Coordinates:** `NSEvent.mouseLocation` and `NSWindow.frame.origin` are both global screen points with a bottom-left origin. Adding press-to-now travel to the origin needs no y-flip.
- **Main thread:** `start_window_drag` is a sync command, so Tauri runs it on the main thread, and it checks `MainThreadMarker` anyway. The monitor's handler runs on the main thread, so the `thread_local` state is sound.
- **Retained objects:** the handler retains the press event with `retain()` and returns the event it was given, so nothing is swallowed. AppKit keeps its own copy of the block, so dropping the `RcBlock` is safe. The monitor is kept in `MONITOR` for the app's lifetime.
- **Dependencies:** the `NSEvent` and `block2` features come from objc2-app-kit 0.3.2's default features.
- **Late requests:** a request that arrives after the release is a no-op because of the held-button check, the `windowNumber` match and clearing on mouse-up.

**Frontend:** `windowDrag.ts` copies drag.js's (tauri 2.12.7) clickable tags, contenteditable, tabindex, the eight interactive ARIA roles, the `"false"` opt-out, and the macOS rule that zoom fires on the second release at the same point. It differs from drag.js in two ways, neither a finding: a triple-click now starts a drag, and a control carrying the attribute can no longer opt in. No element opts in, which the test asserts.
