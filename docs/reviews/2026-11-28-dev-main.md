```
File: src/App.tsx:2435 (effect lands in src/components/FindingPopover.tsx:96-104)
Lens: Verification
Guideline: Every change pairs with a runnable check. New behaviour with no test, in a suite it plainly belongs in, is a finding.
Why: "deep" covers the inspector cap's whole DOM subtree, and that includes FindingChip's FindingPopover. The popover is not portalled; it sits absolutely positioned inside the cap. It has role="dialog", which is not in drag.js's INTERACTIVE_ROLES, and nothing between it and the cap row carries the attribute. So a mousedown anywhere in the open "N flagged" popover now reaches the deep row and returns true. drag.js then calls preventDefault and start_dragging. Pressing on a finding's text drags the window instead of selecting it, and on macOS a double-click there zooms the window. With the bare attribute the walk returned false (el !== target), so this regression is new in this diff. The test checks only the band's own children. (Found by tracing the code, not run in the app.)
Suggested action: Add data-tauri-drag-region="false" to FindingPopover's root div. Add one case to cap_drag_deep.test.tsx: open the chip and assert startsDrag(a finding-popover-line) === false. It should fail before the attribute is added.
```
