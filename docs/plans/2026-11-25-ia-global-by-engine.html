2 · The model: one grid, two filters

The rows are assets and the columns are engines. The backend already knows every cell from get_asset_annotations, which records reach per engine. Picking Claude Code selects the shaded column; a kind tab selects a band of rows.

5 · Phases

Phase 1 · no backend change

  • Remove the Engines tab and migrate its preference
  • Engine chips on every Global tab
  • Filter the list by reach
  • Strip engine mode: MCP figures are real, the other kinds read “Not measured”
  • “Not loaded by …” group
  • Delete EnginesPane and EnginesSidebar

Phase 2 · backend budget

  • Measure, engine by engine, what each loads at startup
  • get_engine_budget: reached count and ≈ tokens per kind
  • Real figures in the strip segments, tab counts and chips

Phase 3

  • The same engine filter on repo screens
